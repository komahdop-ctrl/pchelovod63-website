4. Только по отдельному решению ЦУП/владельца выполнить переключение. До него записать фактические DNS-записи/TTL, сохранить Pages и предыдущую принятую сборку. В этой работе DNS не читались напрямую и не изменялись.
5. При неудачной приёмке staging — оставить production как есть. После будущего переключения — восстановить предыдущий принятый release в каталоге портала; DNS-откат допустим лишь по отдельному разрешению с сохранёнными прежними значениями. Не использовать rsync --delete по общему каталогу и не считать текущую сборку автоматически принятой для полного QA.
6. Выполнить восстановление в изолированной копии, повторить HTTP/manifest/ссылки и зафиксировать время. Сейчас восстановление и откат NOT_TESTED; это план, не проверенный runbook.
