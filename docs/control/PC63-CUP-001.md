## Управление, решения и передача
1. Канонический реестр: этот путь в рабочей ветке и PR до принятия; после merge — main. Следующие сессии сначала читают PR/head и текущий реестр. Память чатов вторична.
2. У каждой работы один ID, ответственный и source SHA. До создания задачи проверить существующие PR/issues. Ревизию результата повышать, не создавать повторный ID.
3. Состояния: PLANNED → IN_PROGRESS → DONE_UNVERIFIED → PASS после собственной проверки; FAIL/BLOCKED с причиной. NOT_TESTED — проверки ещё нет. Отправлено/получено — журнал доставки, не статус готовности.
4. Изменять только собственные строки; перед записью перечитать свежий blob/head. При конфликте объединить, не затирать изменения. ЦУП принимает и фиксирует решение.
5. Обязательная приёмка: версия/среда/команды/результат/артефакт; source, CI и production отдельны. Релиз: разрешённый SHA, backup, откат, live-проверка. Ни один текущий Draft не сливается этим поручением автоматически.
6. Отложенные решения: новый редизайн, домен/поддомен, переключение хостинга и реальный сбор данных не разрешены этим реестром. Политики и меры защиты не выдавать за юридическое заключение.
7. Массовый запуск восьми направлений пока не выполнен: контрольная точка владельца ещё впереди, UI показывает исчерпанный лимит Work. Наличие текущего рабочего сеанса не доказывает возможность запуска новых.
8. Первая очередь после контрольной точки: PC63-06 проверка PR17 совместно с PC63-02; PC63-05 старый Worker и данные; PC63-01 фактический хостинг; затем PC63-03 пересчёт каталога. При недоступном браузере не имитировать визуальные тесты.
9. Подтверждённые решения: сохранить портал и дизайн; сбор данных закрыт; использовать существующие PR и issue11; не включать соседние проекты. Полный переезд Beget не подтверждён и не считается решением.
