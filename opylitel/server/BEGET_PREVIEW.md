# Постоянный канал тестовой публикации на Beget

Состояние: код подготовлен. Подключение аккаунта и первый выпуск на Beget
считаются выполненными только после успешного SSH и проверки опубликованных файлов.

## Схема

Изменения в `beget/opylitel-preview` (или в `main` после включения workflow там)
запускают `.github/workflows/deploy-beget-preview.yml`.
GitHub проверяет изолированное размещение и откат, готовит четыре HTML-страницы,
затем загружает их через SSH только в `<подтверждённый webroot>/opylitel-preview/`.
Это отдельная тестовая копия ОПЫЛИТЕЛЯ, а не миграция всего портала.
Другие каталоги, DNS и действующая публикация GitHub Pages не меняются.

Сбор заявок принудительно выключен в клиентской конфигурации и дополнительно
блокируется CSP `connect-src 'none'; form-action 'none'`. PHP, базы, экспорт,
секреты и реальные заявки в этот канал не входят. Эта проверка не заменяет
приёмку backend, HTTPS API, резервирования БД или юридической готовности из
`COMPLIANCE.md` и `LAUNCH.md`.

## Единовременное подключение

Защищённые настройки Actions этого репозитория должны содержать:

| Имя | Значение |
|---|---|
| `BEGET_HOST` | Подтверждённый SSH-сервер аккаунта |
| `BEGET_USER` | Логин аккаунта |
| `BEGET_WEB_ROOT` | Реальный абсолютный путь к публичному каталогу тестового сайта |
| `BEGET_PREVIEW_URL` | HTTPS-адрес, заканчивающийся `/opylitel-preview/` |
| `BEGET_SSH_KEY` | Отдельный ключ автоматической публикации в OpenSSH-формате, без интерактивного запроса пароля |
| `BEGET_KNOWN_HOSTS` | Заранее проверенная запись ключа SSH-сервера из доверенного источника |

Не помещать ключ в чат, исходники, issue, PR, артефакты или логи.
Не отключать проверку ключа сервера и не доверять непроверенному `ssh-keyscan`.
Предпочесть отдельный ограниченный ключ публикации, а не личный ключ с доступом
ко всему аккаунту. Наличие прав на изменение кода не означает наличие права
управлять Actions Secrets: это отдельная возможность интеграции/владельца.
Подключённый здесь GitHub-инструмент не предоставляет запись Actions Secrets.
Поэтому настройку доступа нельзя объявить выполненной одним добавлением workflow.

Один ключ без подтверждения каталога и адреса не является готовой конфигурацией.
Определить их по аккаунту, не угадывать путь и не выбирать чужой сайт.
При отсутствии любого параметра выпуск завершается понятным отказом до SSH.
После однократного подключения обычные обновления не требуют ручных действий владельца,
пока доступ действителен и работа остаётся в пределах этой тестовой площадки.

## Проверка и откат

SSH выполняется из GitHub runner, а не из среды чата; это другой сетевой маршрут,
но его доступность тоже должна быть подтверждена первым реальным запуском.
На стороне Beget требуется Python 3.8+ и стандартный OpenSSH-доступ.

Публикация разрешена только в новый каталог либо в ранее созданный этим механизмом
каталог с меткой проекта в `release.json`. Симлинк вместо каталога запрещён.
Архив проверяется по строгому списку файлов, типам записей и SHA-256.
Предыдущая тестовая версия сохраняется вне текущего webroot в закрытом каталоге
`.opylitel-preview-backups` рядом с ним. В нём только статика, без заявок.
Автоматической очистки предыдущих выпусков пока нет; размер нужно контролировать.

После загрузки проверяются по HTTPS манифест и SHA-256 всех четырёх страниц.
Ответ HTTP 200 сам по себе не считается успешной публикацией.
При трёх неудачных проверках содержимого вызывается откат предыдущей версии;
при первом выпуске неудачная копия убирается с публичного пути.
Если после загрузки пропадёт SSH-доступ, автоматический откат может не выполниться —
это авария, а не подтверждённый откат. Факт отката проверять по результату запуска.

Этот канал не устанавливает SSL-сертификат и не подтверждает операторские документы.
HTTPS тестового адреса должен быть настроен до первого успешного выпуска.
