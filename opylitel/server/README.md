# ОПЫЛИТЕЛЬ.РУ — сервер заявок 2027

`intake.php` — подготовленный обработчик заявки с валидацией полей, ограничением частоты и сохранением в SQLite с возвратом уникального номера. **В production пока НЕ развёрнут.** Основной сайт сейчас публикуется как статический GitHub Pages.

Список юридических и организационных блокеров: [COMPLIANCE.md](./COMPLIANCE.md). Текущие публичные `privacy.html` и `consent.html` — **НЕУТВЕРЖДЁННЫЕ ПРОЕКТЫ**.

## До начала публичного сбора персональных данных

1. Определить оператора персональных данных (ИП или организация): ФИО/название, реквизиты, контакт, адрес, лицо для запросов субъектов. Проверить обязанности уведомления Роскомнадзора.
2. Подготовить юридически проверенную политику и текст согласия (категории данных, цели, срок обработки, удаление, способы отзыва).
3. Выбрать подходящий российский HTTPS/PHP 8.1+ хостинг для API и БД с защищённым доступом; проверить PDO SQLite и mbstring.
4. Разместить API на отдельном домене/поддомене, например `https://api.pchelovod63.ru/intake.php`, если DNS и сервер позволяют. База SQLite — **только вне webroot**, права только у процесса PHP. Настроить резервирование, контроль доступа, аудит, сроки удаления.
5. Задать **только на сервере** переменные: `OPYLITEL_DB_PATH=/absolute/path/outside/webroot/opylitel.sqlite`, `OPYLITEL_HASH_SALT=<случайная строка от 32 символов>`, `OPYLITEL_ALLOWED_ORIGINS=https://pchelovod63.ru,https://www.pchelovod63.ru`, `OPYLITEL_CONSENT_VERSION=<номер одобренного согласия>`, `OPYLITEL_CONSENT_SHA256=<SHA-256 утверждённого HTML согласия>`, `OPYLITEL_LEGAL_READY=1` **только после оформления документов**, `OPYLITEL_WEB_ROOT=/absolute/path/public_html` и `OPYLITEL_SITE_HTTPS_READY=1` после проверки HTTPS. Включить `OPYLITEL_ACCEPTING=1` только после юридической и технической приёмки.
6. В `opylitel/index.html` установить `window.OPYLITEL_INTAKE={endpoint:'https://api.pchelovod63.ru/intake.php',enabled:true,legalDocumentsApproved:true,consentVersion:'<тот же номер одобренного согласия>'}`. Сейчас отправка намеренно **отключена**.
7. Проверить положительный сценарий (код заявки), валидацию, rate limit, поведение при недоступном сервере и отсутствие доступа к БД из браузера. Защитить будущую админку, не делать публичных API с именами, телефонами или координатами.

## Анкета

Обязательные: контактное имя, телефон, регион, район/населённый пункт, **количество семей, готовых на выезд**, максимальное расстояние, месяцы, согласие. Необязательные: общее число семей, культуры, примечание и уточнение минимальной партии/цены. Телефон — единственный обязательный контакт, дополнительный мессенджер не собирается. Цена за 1 семью включает перевозку, погрузку и обратный вывоз. Схема заявки — v3. **Не собираем точные координаты**. Согласие и политика пока не готовы, поэтому текущий интерфейс — демонстрация, а не приём.

## Каналы связи по этапам

На первом этапе — **только телефон**; MAX и Telegram не запрашиваются в анкете. Во время предварительного подбора и торга контактные данные сторон скрыты, доступна только асинхронная переписка по заявке с предварительной модерацией координатора.

**При переходе к оформлению договора с аграрием** владелец пасеки и уполномоченные помощники могут самостоятельно привязать MAX и/или Telegram к профилю. Номер телефона **не является автоматическим подтверждением владения бот-аккаунтом**: требуется проверенный одноразовый код/привязка внутри бота.

В контрактной и операционной фазе боты отправляют уведомления каждому участнику команды. Критические уведомления об обработках и изменениях сроков должны собирать персональные подтверждения, а неполученные/неподтверждённые сообщения эскалируются к координатору и телефонному контакту.

## Неприкосновенность публичных данных

В публичном интерфейсе только агрегированное количество семей по региону, без ПД и точных адресов. Право на доступ к закрытой базе имеет только оператор/уполномоченный координатор. Контакты с аграриями проходят через координатора. Система безопасности уведомлений о пестицидах — отдельный критический контур следующего этапа.

## Закрытое управление и тесты

`preflight.php` запускается только из CLI на **целевом** сервере и показывает, какие условия ещё не выполнены, без отображения секретов. `manage.php` позволяет выполнить `init`, `stats`, `public-stats`, `export /PRIVATE/PATH.csv`, `delete B27-...`. Файл используется только в командной строке, не выкладывайте базу и экспорт в `public_html`. Подробный план запуска — [`LAUNCH.md`](./LAUNCH.md). Автоматические тесты — `.github/workflows/verify-opylitel.yml`.
