# ОПЫЛИТЕЛЬ.РУ — план безопасного запуска приёма заявок (23.10.2026)

Статус: публичная бета-страница открыта, **отправка данных выключена**. Проект размещён на GitHub Pages; GitHub Pages не исполняет PHP и не является местом для хранения личных данных. Backend следует разместить отдельно.

## Предпочтительная техническая схема

- Публичная витрина и анкета: `https://pchelovod63.ru/opylitel/` (GitHub Pages, без базы).
- Приём заявок: отдельный HTTPS-поддомен на сервере **на территории России** — например, `api.pchelovod63.ru` (DNS настроить только после размещения).
- PHP-скрипт: `intake.php` в публичном каталоге API-сайта.
- База данных: SQLite **вне публичного каталога**. В документации Beget root аккаунта отличается от `public_html`; фактический путь проверяем в панели.
- Админская утилита: `manage.php` размещается **вне публичного каталога** и вызывается только по SSH. Она не имеет веб-админки.
- Журналы доступа, бэкапы и любые экспортированные CSV с телефонами должны остаться в защищённой российской инфраструктуре. Не отправлять CSV и SQLite в публичный GitHub, ChatGPT, иностранные облачные сервисы и мессенджеры без отдельной юридической оценки.

Beget подтверждает, что виртуальный хостинг находится в России: https://beget.com/ru/blog/2026/faq-po-tekushhej-situaczii . При этом местонахождение сервера **само по себе не гарантирует соответствия 152-ФЗ**. Beget предлагает отдельное аттестованное облако 152-ФЗ: https://beget.com/ru/news/2026/oblako-beget-sootvetstvuet-152-fz . Возможность использовать текущий тариф нужно выяснить по конкретному аккаунту и требуемым мерам защиты.

## Точки, зависящие от решения владельца

1. Установить **оператора персональных данных** (ИП/организация), его полное имя или название, адрес, email/контакт, лицо для обработки обращений и правовые основания.
2. Подготовить согласие **отдельным документом** и политику обработки на сайте. Не использовать текущую страницу `privacy.html` как готовую политику — это предупреждение о разработке.
3. Проверить обязанности уведомления Роскомнадзора до начала обработки, определить уровень защищённости и меры защиты; получить юридическую оценку. Закон: https://www.consultant.ru/document/Cons_doc_LAW_61801/cbf4e15b7c330f9372e876cdf2bc928bad7950ef/
4. Подтвердить российскую локацию сервера, работоспособность PHP 8.1+, `mbstring`, `pdo_sqlite`, возможность SSH и записи за пределами `public_html`; продумать бэкапы, разграничение доступа и удаление данных.
5. **Только после проверки** подтвердить прием реальной тестовой заявки в приватной БД, получить номер и удалить тестовую запись.

## Настройка backend (только после пунктов выше)

На сервере, в защищённой конфигурации, определить значения:

```bash
OPYLITEL_DB_PATH=/absolute/private/path/opylitel.sqlite
OPYLITEL_HASH_SALT=<случайная_секретная_строка_длиной_не_менее_32>
OPYLITEL_ALLOWED_ORIGINS=https://pchelovod63.ru,https://www.pchelovod63.ru
OPYLITEL_CONSENT_VERSION=<реальный_номер_одобренного_согласия>
OPYLITEL_ACCEPTING=0
OPYLITEL_LEGAL_READY=0
OPYLITEL_WEB_ROOT=/absolute/path/to/api/public_html
OPYLITEL_SITE_HTTPS_READY=0
```

Секреты не записывать в `.env` в публичном каталоге и не загружать в GitHub. Если PHP-процесс хостинга не видит переменные окружения, выбрать поддерживаемый сервером безопасный способ конфигурации **вне webroot**.

```bash
php /private/path/preflight.php   # диагностирует готовность до включения, не читает заявки
php /private/path/manage.php init
php /private/path/manage.php stats
php /private/path/manage.php public-stats
php /private/path/manage.php export /private/exports/opylitel-2027.csv
php /private/path/manage.php delete B27-AABBCCDDEE
```

Для подготовки публичных агрегатов скрипт `public-stats` не отображает счётчики при числе заявок меньше 5 и скрывает региональные группы меньше 5. Формат пригоден для будущей интеграции, но автоматически на публичный сайт ничего не загружает. Не смешивать **пчеловодов, предварительно заявивших готовность**, с подписанными договорами.

Для активации **после всех условий**: сначала выставить `OPYLITEL_LEGAL_READY=1` после юридической проверки, затем `OPYLITEL_SITE_HTTPS_READY=1` после проверки SSL и `OPYLITEL_ACCEPTING=1` в настройках сервера, а во фронтенде установить `window.OPYLITEL_INTAKE={endpoint:'https://api.pchelovod63.ru/intake.php',enabled:true,consentVersion:'<тот_же_номер_согласия>'}`. Проверить CORS, недоступность базы по URL, валидность HTTPS, серверные ошибки и запись в SQLite.

## Автоматические тесты

Workflow `.github/workflows/verify-opylitel.yml` поднимает тестовый PHP-сервер с фиктивным именем и телефоном, проверяет запись в SQLite, ограничения на Origin, обработку ошибки, агрегаты, экспорт CSV и удаление. **Успешный CI не заменяет проверку реального сервера и выполнение требований закона**.

## Оставшиеся этапы разработки

- Бета пчеловодов: настоящий приём заявок с фиксацией версии согласия.
- Панель координатора с двухфакторной авторизацией, историей действий, подтверждением актуальности и отметками обработки.
- Отдельная форма агрария: организация → регионы → районы → поля, с 1–5 ответственными на поле.
- Общий профиль и интеграция MAX/Telegram **только на этапе согласования условий и заключения договора с аграрием**: добровольная подтверждённая привязка бота к профилю. Предварительные заявки — только телефон; переговоры до договора — через модерируемую закрытую переписку. Ежемесячная проверка актуальности заявок независимо от мессенджеров.
- Контур критических уведомлений о пестицидах: **индивидуальное подтверждение каждого получателя** и эскалация неподтверждённых сообщений, отдельно от приёма заявок.
