## Исправления безопасности и восстановления

- Отдельный JSONL ledger записывается и синхронизируется в момент каждого удаления ДО удаления БД. Его события применяются при старте и restore, поэтому утрата основной БД при сохранённом ledger не воскрешает старые анкеты. Повреждённый ledger блокирует операцию. Сам ledger требует независимого долговечного хранения — другая папка того же диска не считается независимым backup.
- Restore проверяет hash manifest и SQLite integrity ДО замены. Candidate создаётся отдельно, мигрируется, очищает sessions, применяет ledger и проходит integrity; только затем atomic rename. Повреждённая копия/ledger оставляют основной файл неизменным.
- DB lease запрещает вторую запущенную инстанцию и restore/switch при активном либо непроверенном stale lock. Stale lease не удаляется автоматически. Backup/manifest/stage приватны, fsync/права0600, symlink/hardlink отклоняются, включая dangling symlink.
- Версии/хеши миграций хранятся в `_opy_migrations`; повтор идемпотентен, неизвестная новая миграция или изменение применённого SQL блокирует старый/изменённый сервер.
- Hosted Node adapter использует явный HTTPS publicOrigin, проверяет Host, игнорирует Forwarded headers, выдаёт Securecookie; публикует только whitelist статических путей. server/tests/deploy/configJSON не отдаются черезHTTP. Прямой dev-server остаётся loopback.
- Persona '__proto__'/constructor больше не обращается к прототипу реестра: отклоняется422. Ужесточены bbox и обратный диапазон дат. Подпись площади уточнена: сфера6371008.8м, не кадастр.

## Почему предпросмотр может показать refused to connect

HTTP к существующей иностранной демонстрации r2: без авторизации `/`403 и `/api/fields`403; служебный авторизованный `/`200 и `/api/health`200 с realIntake:false. Эффективный HTML CSP содержит `frame-ancestors 'none'`. НастройкиSite custom допускают только владельца, внешних приглашений 0. Следовательно, iframe запрет подтверждён, сбой доступности по этим данным не установлен. Локальный браузерный тест воспроизвёл блокировку iframe при прямой доступности.

Служебный 200 НЕ заменяет проверку человеческого входа владельца; она в общей браузерной сессии не выполнялась по запрету параллельного управления. Открывать для владельца следует прямой верхнеуровневый URL: https://opylitel-2027-test.komahdop.chatgpt.site . Ни CSP, ни accesspolicy для обхода предпросмотра не ослаблялись. Иностранная демоверсия остаётся r2; r3 переносимыйсервер готовится отдельно вPR13.

## Установка и откат

См. deploy/ENVIRONMENT.md. Синтетический mode единственный, настоящий /api/intake всегда 503. Российскому стенду нужен Node 24.xnativeSQLite и постоянный loopback-процесс, отдельный TLS vhost с owner-only auth gate перед ВСЕМИ маршрутами, приватные data/ledger/backup вне webroot, ограниченное управление процессом и подтверждение географии сервера/копий. Типовой PHP shared hosting не объявляется совместимым без проверки.

systemd template статически проверен после подстановки фактического Node binary/пути; `/usr/bin/node` в шаблоне нужно адаптировать. Nginx binary в среде отсутствует: nginx -t NOT_RUN, unit не установлен. releasecontrol переключает symlink, сам не запускает сервис/не меняетDNS/nginx/systemd. Неизвестнаясхема блокирует rollback, нет автоматическогоDROP/downmigration; при необходимости отдельныйrestore cактуальнымledger.
