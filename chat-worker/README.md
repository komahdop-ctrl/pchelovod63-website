# 🐝 «Улей общения» — мини-чат «ПЧЕЛОВОД 63»

Интерфейс мини-чата автоматически подключается ко всем страницам, которые собирает Vite.
Основной сайт остаётся на GitHub Pages; сервер чата работает отдельно на Cloudflare Workers + Durable Objects (SQLite).

## Статус
- ✅ Интерфейс, адаптивный для телефона и компьютера.
- ✅ Клиент WebSocket: общие сообщения, последние 100 сообщений, псевдонимы и онлайн.
- ✅ Серверная часть в `chat-worker/`: 30 дней хранения, ограничение 500 символов, 5 секунд между сообщениями, проверка Origin, защищённое удаление сообщений администратором.
- ⏳ **Сервер ещё нужно развернуть в личном аккаунте Cloudflare.** Пока `public/chat-config.js` содержит пустой адрес, посетителям честно показывается сообщение «Скоро откроем».

## Самый простой запуск — через сайт Cloudflare (без терминала)

1. В https://dash.cloudflare.com/ откройте **Workers & Pages → Create application → Import an existing Git repository**.
2. Подключите GitHub и выберите репозиторий `komahdop-ctrl/pchelovod63-website`, ветку `main`.
3. Укажите **Root directory**: `chat-worker` (важно: не корень всего сайта). Команда развёртывания — `npx wrangler deploy`; имя Worker — `pchelovod63-chat`.
4. Запустите развертывание. Полученный адрес вида `https://pchelovod63-chat.<ваш-поддомен>.workers.dev` проверьте через `/health`.
5. В настройках Worker **Variables and Secrets** добавьте секрет `ADMIN_TOKEN` для удаления нежелательных сообщений. Не присылайте и не публикуйте его.
6. В файле `public/chat-config.js` основного сайта укажите `wss://pchelovod63-chat.<ваш-поддомен>.workers.dev/chat`, затем опубликуйте GitHub Pages.

Cloudflare автоматически собирает Worker из GitHub при изменениях кода после подключения репозитория. Сам сайт остаётся на GitHub Pages. Не включайте открытый чат без плана модерации и правил общения.

## 1. Развёртывание (с компьютера Windows или macOS)

Нужны Node.js, доступ к личному аккаунту Cloudflare и открытый GitHub-репозиторий.

```sh
cd chat-worker
npx wrangler login
npx wrangler deploy
```

Cloudflare выведет адрес Worker, похожий на `https://pchelovod63-chat.<название-аккаунта>.workers.dev`.

Создайте секрет администратора (случайный длинный пароль; не помещать в GitHub и не публиковать на сайте):

```sh
npx wrangler secret put ADMIN_TOKEN
```

Проверьте адрес: `https://<адрес-worker>/health` должен вернуть `{"ok":true,...}`.

**Важно:** в `wrangler.jsonc` параметр `ALLOWED_ORIGINS` содержит список допустимых доменов сайта. Обновите его при смене домена, указывайте точные Origins без завершающего слэша, например `https://komahdop-ctrl.github.io`. Не используйте `*`.

## 2. Связать сайт с сервером

Откройте `public/chat-config.js` и вставьте полный адрес WebSocket (замените HTTPS на WSS):

```js
window.P63_CHAT_WS_URL = "wss://pchelovod63-chat.<название-аккаунта>.workers.dev/chat";
```

Закоммитьте изменение в GitHub. После автоматической пересборки GitHub Pages чат заработает **на всех собираемых страницах**. Никаких API-ключей Cloudflare в браузер добавлять не нужно.

На телефоне и компьютере откройте разные окна сайта, введите имена, проверьте передачу сообщений и число присутствующих. Чат учитывает только открытые активные вкладки (скрытые вкладки не считаются онлайн). Посетитель с псевдонимом не считается подтверждённой личностью.

## 3. Модерация

Администратор может удалить сообщение по его `id` через HTTP-запрос:

```sh
curl -X POST "https://<адрес-worker>/admin/delete" \
  -H "Authorization: Bearer <ваш-ADMIN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"id":"<идентификатор-сообщения>"}'
```

Идентификаторы присутствуют в WebSocket-сообщениях `type:"message"`, доступны через инструменты разработчика в браузере. Удаление распространяется подключённым посетителям в реальном времени.

Пока нет графической панели администратора, проверки личности, устойчивых IP-банов и фильтра нежелательного контента — **не считать публичный анонимный чат защищённым от спама без модерации**. Перед публичным запуском рекомендуется добавить кнопку жалобы, удобную панель модератора и дополнительный антиспам (например, Turnstile или Cloudflare Rate Limiting). Не публикуйте пароль в исходниках.

## 4. Устройство

- `vite.config.ts` вставляет `chat-config.js`, `chat-widget.js` и `chat-widget.css` при каждой сборке HTML.
- `public/chat-widget.js` показывает виджет и поддерживает WebSocket с автопереподключением.
- `chat-worker/src/index.js` обрабатывает подключения в одном Durable Object и хранит сообщения в SQLite.
- Сообщения удаляются через 30 дней (очистка выполняется при следующем подключении).
- Онлайн — число уникальных случайных идентификаторов браузера среди активных вкладок; значение приблизительное.
- Для сохранения имени браузер использует `localStorage`. Личные данные вроде телефона и почты не запрашиваются.

**До включения публичного чата:** разместите понятные правила общения и информацию об обработке данных, проверьте правовые требования и организуйте регулярную модерацию.
